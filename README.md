# 开桌 · 桌游社网站

每周五 18:30 · R312 桌游活动的主页、游戏库和预约报名系统。

| 页面 | 地址 | 说明 |
|---|---|---|
| 主页 | `/` | 科幻风格首页：倒计时、本场战况（各游戏报名人数与成桌进度）、游戏舱、常见问题 |
| 游戏库 | `/games` | 按人数 / 时长 / 难度 / 分类筛选；每款游戏有介绍、规则速览、B 站教学视频和「讲规名单」（会讲的同学自己挂名 / 撤下） |
| 报名 | `/signup` | 国漫群像背景；选场次 → 按喜欢程度依次点选游戏（志愿不限个数）→ 选参加哪几轮 → 填称呼、熟悉程度、可选 4 位找回码 → 提交 |
| 我的报名 | `/me` | 这个浏览器里报过的名：每轮分到哪一桌、和谁同桌；修改 / 取消；换了浏览器用找回码找回 |
| 管理后台 | `/admin` | 名单（志愿顺序、每轮分配）、签到、按轮分桌与打印、重新自动分桌、场次与轮次（停办 / 换教室 / 加场 / 改轮数）、桌游维护、导出 Excel、备份与回滚 |

## 报名规则（系统自动执行）

- 每周五自动生成场次，默认开放未来 3 周的预约；**开局（18:30）前都可以报名和修改**，开局后线上报名关闭。
- 一晚分多轮（默认两轮：18:30–20:15、20:15–22:00，后台可改，最多 4 轮）。每人报一次，排一份志愿顺序，选参加哪几轮。
- 每一轮按志愿顺序分桌：每款游戏按「每桌人数 × 拥有套数」计算座位，按报名（改志愿则按修改）先后入座；排在前面的志愿满员或凑不齐最少人数，就顺延到下一个志愿；每个志愿都凑不齐的人列为「未成桌」，组织者现场协调。
- 同一个人不会两轮分到同一款游戏。首页「本场战况」按全部志愿统计意向人数（不只第一志愿）。
- **讲规名单**：会讲某款游戏规则的同学可以在游戏库里挂名（以称呼，长期有效，自己的设备上随时撤下；管理员可代挂 / 删除）；报名表里勾「我能讲规的游戏」也会挂上去（只添加不删除）。想提前学的同学可以在群里问挂名的人。
- 当晚每一桌都会标出讲规情况：本桌有人会讲 → 显示是谁；本桌没人会讲 → 列出本轮到场、挂名会讲这款的人和他们坐在哪（没上桌的排最前），请他过来讲几分钟；都没有 → 提示先看教学视频或在群里问挂名的人。系统只显示，不指派。报名的称呼和挂名的称呼一致才认得出来。
- 人数够开多桌时各桌人数均衡；挂名会讲这款的人优先分散到这款游戏的不同桌，其次是老手。
- 活动开始时分桌自动锁定：之后取消的人从桌上移除，新来的人只补进有空位的桌，不打乱已开局的桌；管理员可以在后台「重新自动分桌」。
- 同一场次同一个称呼只能报一次。修改 / 取消凭报名时那台设备上保存的凭证；报名时设了 4 位找回码的，换浏览器可在「我的」页面找回（同一条报名 1 小时内最多猜错 5 次）；没设的请联系管理员在后台处理。
- 公开页面只显示称呼和分桌，备注只有管理员能看到。

## 部署到 Render

1. 把整个 `boardgame-club` 文件夹的内容放到 Render 服务关联的 GitHub 仓库根目录（覆盖旧文件）。
2. Render 服务设置：
   - **Build Command**：`npm install`
   - **Start Command**：`npm start`
3. 环境变量（Render → 服务 → Environment）：

| 变量 | 必填 | 说明 |
|---|---|---|
| `ADMIN_KEY` | 是 | 管理后台密钥，自己设一个足够长的随机字符串（至少 12 位）。也兼容 `ADMIN_PASSWORD`。 |
| `DATABASE_URL` | 强烈建议 | Postgres 连接串。**不配置时数据存在服务器本地文件里，Render 免费实例休眠 / 重启 / 重新部署都可能清空报名数据。** |
| `PGSSL_NO_VERIFY` | 否 | 默认会校验数据库的 TLS 证书（Neon 无需设置）。只有自签证书的数据库才设为 `1`。 |

部署后检查：打开 `/healthz` 显示 `ok` 表示服务和数据库都正常（数据库不可用时返回 503）；后台「数据与设置」会显示当前是数据库存储还是文件存储。

### 多管理员

- **所有者**：用 Render 环境变量里的 `ADMIN_KEY` 登录 `/admin`。
- **协作管理员**：所有者在后台「数据与设置 → 协作管理员」里填名字添加，系统生成一把专属密钥（只显示一次，私聊发给对方）。协作管理员可以管理名单、签到、场次、桌游、设置和导出；**添加 / 撤销管理员、导入备份、恢复历史版本只有所有者能做**。撤销后对方密钥立即失效，恢复历史版本也不会把已撤销的密钥带回来。
- 「操作记录」里能看到谁在什么时候代报名、删除、签到、改场次 / 桌游 / 设置、导入或恢复（保留最近 500 条）。

### 安全与防刷

- 每个 IP 每 10 分钟最多 80 条成功报名（只计成功的，校园网多人共用出口 IP 也够用），失败请求另有上限；每场最多 300 人。
- 管理员密钥错 10 次后该 IP 锁 10 分钟（全站累计 200 次也会锁），正确登录不受影响。
- 报名凭证由手机端生成并只保存在本机；网络中断时重新提交不会重复报名。

### 免费数据库（Neon，约 3 分钟）

1. 打开 <https://neon.tech> 注册并创建一个 Project（Region 选离 Render 服务近的，如 Singapore）。
2. 在 Dashboard 的 *Connection string* 复制以 `postgresql://` 开头的连接串。
3. 粘贴到 Render 的环境变量 `DATABASE_URL`，保存后服务会自动重启。
4. 打开 `/admin` →「数据与设置」，看到「✓ 数据保存在 Postgres 数据库」即成功。

系统首次启动会自动建表（`bgc_state`、`bgc_backup`），并写入游戏库初始数据。每次修改都会自动保存一个历史版本（保留最近 200 个），可在后台一键回滚。

### 从旧版网站迁移数据

旧版网站后台「导出备份」得到的 JSON，可以在新后台「数据与设置 → 导入备份」直接导入，会合并进现有数据。

### 可选：减少“首次打开要等半分钟”

Render 免费实例闲置 15 分钟后会休眠，下一位访客要等 30–60 秒唤醒（页面会显示“服务器正在唤醒”提示；同一台设备第二次打开会先用缓存秒开）。

如果仓库是 **公开** 的，可以启用仓库里自带的 `.github/workflows/keepalive.yml`：在 GitHub 仓库 *Settings → Secrets and variables → Actions → Variables* 新建变量 `KEEPALIVE_URL`，值为网站地址（如 `https://boardgame-club.onrender.com`）。它会在每天 08:00–24:00（UTC+8）每 10 分钟访问一次 `/healthz`。私有仓库会消耗 GitHub Actions 免费分钟数，不建议开启。

## 本地运行

```bash
npm install
ADMIN_KEY=test npm start      # Windows PowerShell: $env:ADMIN_KEY="test"; npm start
```

打开 <http://localhost:3000>。运行测试：`npm test`。

## 目录结构

```
server.js          HTTP 服务：静态文件（预压缩 + 缓存）与 JSON API
lib/logic.js       场次时间、数据校验、自动分桌（纯函数，有单元测试）
lib/store.js       存储：Postgres 或本地 JSON 文件，自动历史版本
data/seed.json     首次启动时写入的游戏库（含教学视频）
public/            页面、样式、脚本、角色插画（assets/chars/*.svg）
test/              分桌与时间逻辑的单元测试
```

报名页的角色均为原创 Q 版致敬绘制（SVG），未使用任何官方图片素材。
